# Клон «Skull King Kraken» + голосовые команды

Этот файл читается в начале каждой сессии. Подробности:
- `docs/original-spec.md`: что известно об оригинале (экраны, данные, формула очков, строки en/ru, чек-лист для проверки вживую);
- `docs/voice-design.md`: голосовой ввод и отсев шума;
- `voice-core/`: готовый парсер голосовых команд с тестами (чистый TypeScript).

## Цель
Приложение-счётчик очков для карточной игры Skull King. Нужно максимально повторить оригинал по **логике, UX и визуалу**, затем добавить голосовой ввод с надёжным отсевом шума. Стек не обязан быть Flutter.

## Что известно об оригинале
- Живая версия: https://skullkingkraken.github.io/skullkingkrakenapp/
- Репозиторий: https://github.com/skullkingkraken/skullkingkrakenapp. Ветка `main` содержит только README, ветка `pwa` содержит готовую сборку Flutter web (31 файл). Исходников Dart нет ни в одном коммите, других публичных репозиториев у аккаунта нет.
- Логика, модель данных, формула очков и тексты en/ru уже восстановлены из минифицированного `main.dart.js`: `docs/original-spec.md`. Это реконструкция: сверяй с живым приложением, расхождения записывай в `docs/deviations.md`.
- Flutter web рисует интерфейс на canvas, DOM почти пустой. Структуру смотри по скриншотам. Можно попробовать включить дерево семантики: `document.querySelector('flt-semantics-placeholder')?.click()`; после этого в DOM могут появиться узлы с aria-label.

## Стек по умолчанию (можно менять, тогда поправь эту строку)
React + TypeScript + Vite, PWA (офлайн, localStorage), портретный режим, русский и английский. `voice-core/` переиспользовать как есть.

Целевая платформа: сайт в браузере телефона (390×844), десктоп и адаптив не нужны.

Код: `src/game/model.ts` (модель и правила, чистые функции), `src/App.tsx` (состояние и навигация), `src/screens/*` (экраны: пропсы на вход, колбэки на выход), `src/i18n.ts` (строки). Проверки: `npm test`, `npx tsc --noEmit`, e2e на клоне `node tools/explore/clone-e2e.mjs` и голос `node tools/explore/voice-e2e.mjs` (нужен `npm run dev`), тесты `voice-core`: `cd voice-core && npm test`. Визуальное сравнение с оригиналом: `node tools/explore/clone-shots.mjs [--only=NN]` и `node tools/explore/compare.mjs [NN]` → `reference/compare/`. Стили: глобальные в `src/app.css` (подключается раньше экранов), экранные в `src/screens/*.css`.

Деплой: репозиторий https://github.com/efValeron/skullking, сайт https://efvaleron.github.io/skullking/. Пуш в `main` → workflow `.github/workflows/deploy.yml` (тесты, сборка, GitHub Pages). PWA через `vite-plugin-pwa`, проверка офлайна: `npx vite preview --port 4173` и `node tools/explore/pwa-check.mjs`. Иконки: `public/icons/icon.svg` → `node tools/explore/make-icons.mjs`. Папка `reference/` в git не входит (сборка и скриншоты оригинала): восстанавливается шагами этапа 1. Исследование оригинала: `tools/explore/` (`sh restart.sh`, `sh d.sh '{"op":"texts"}'`).

## План
### Этап 1. Исследование оригинала (код приложения ещё не писать)
1. `git clone -b pwa --single-branch https://github.com/skullkingkraken/skullkingkrakenapp reference/original-build`, раздать локально (`npx serve reference/original-build -l 8080`) или открывать живую версию. Service worker кэширует файлы: использовать чистый контекст браузера.
2. Поставить Playwright (`npm i -D playwright`, `npx playwright install chromium`) и сделать скрипт с эмуляцией телефона (viewport 390×844, deviceScaleFactor 2, hasTouch) в локалях ru-RU и en-US. Если подключён Claude in Chrome (`claude --chrome`), можно исследовать и через него.
3. Пройти весь сценарий по чек-листу из `docs/original-spec.md` (раздел 7). Снять скриншот **каждого** экрана и состояния в `reference/screens/NN-имя.png` (пустые, заполненные, с ошибкой, диалоги, нижние листы, 3 и 7 игроков).
4. Записать наблюдения в `docs/original-ux.md`: компоновка, отступы, размеры, цвета (hex по пикселям), шрифты, анимации и переходы, поведение кнопки «Назад» и клавиатуры.
5. Сыграть 3–4 раунда и сверить очки с формулой из спецификации. В DevTools посмотреть ключи и формат localStorage.
6. Показать итог этапа и план этапа 2.

### Этап 2. Логика и экраны без стилизации
Модель, сохранение, подсчёт очков (чистые функции с юнит-тестами на примерах из оригинала), экраны в порядке из спецификации, диалоги подтверждения, «Продолжить» и «Предыдущие игры».

### Этап 3. Визуал и UX
Сделать вёрстку и анимации. Сравнивать скриншоты клона с `reference/screens` на том же вьюпорте (pixelmatch или odiff), итерировать, пока различия не станут мелкими. Осознанные отличия вести в `docs/deviations.md`.

### Этап 4. Голос
По `docs/voice-design.md` и с `voice-core/`: кнопка «Говорить», черновик с подтверждением, окна имён, ставок и итогов, адаптер Web Speech API за интерфейсом, тесты. Новые шумовые фразы добавлять в `voice-core/cases.json`.

### Этап 5. PWA и деплой
Manifest, service worker, офлайн, деплой на GitHub Pages, проверка на реальном телефоне.

## Правила работы
- Перед каждым этапом коротко покажи план и жди подтверждения. Используй субагентов для параллельной работы (например: исследование UI, реализация, тесты, сравнение скриншотов).
- Не выдумывай поведение оригинала: если не уверен, проверь в живом приложении.
- Не копируй оригинальные картинки (`background.png`, `appbar_background.png`, `card_background.png`) в публичную сборку: используй как референс и сделай свои (CSS, SVG или новые изображения). Шрифт: Pangolin из Google Fonts.
- Тексты интерфейса бери из таблицы строк в `docs/original-spec.md`; язык выбирается по локали браузера.
- Голос никогда не пишет в состояние игры напрямую: только в черновик, который подтверждает пользователь.
- Пользователь общается по-русски: отвечай по-русски, код и идентификаторы на английском.
